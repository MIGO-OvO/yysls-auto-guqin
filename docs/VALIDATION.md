Win32 测试通过真实窗口消息循环记录按键、扫描码和抬起位。它验证发送与普通窗口接收，不证明游戏支持；接收记录位于本机构建的 `artifacts/windows-input.json`。

接收窗口的 `GetKeyState(Shift/Ctrl)` 始终为 0。定向消息到达并不会同步系统键盘状态；游戏若轮询该状态，半音组合仍可能失效。

原生联测在隔离 GitHub runner 执行，日志、截图、窗口接收记录和 JSON 报告保存在对应工作流的 Artifacts 中。Windows 游戏内逐音验收按当前环境保留未验收状态。

## 游戏验收步骤

1. 打开游戏乐器的 36 键模式，记录游戏版本、系统、窗口模式、权限和所选输入方式。
2. 导入 [36 键测试谱](../examples/36-keys.txt)，逐音听辨 C3–B5 的 36 个音。每音按住 150ms、间隔 200ms，全长 12.6 秒。
3. 单独验证 `Shift+Z/A/Q`、`Shift+V/F/R`、`Shift+B/G/T`、`Ctrl+C/D/E`、`Ctrl+M/J/U`，检查修饰键抬起后自然音是否恢复。
4. 后台模式切到文本编辑器，确认游戏继续接收而文本编辑器没有收到字符；记录按键丢失与半音错误。
5. 在长音中暂停、停止、关闭目标窗口，并在托盘菜单退出；检查无持续按键。前台模式切走后应停止。
6. macOS 撤销辅助功能权限，确认应用报告权限丢失并停止；重新授权后必须由用户重新开始。
7. 不接收或音高不完整时标记不兼容，改用前台模式，不把 API 返回值写成通过。

## 更新验收步骤

使用旧版本检查 GitHub `latest.json`，核对版本、日志、下载进度与签名；篡改包必须拒绝安装。下载完成后应保持运行，直到用户确认；确认后保存曲库、停止演奏、安装并重新启动。网络断开、404、签名错误需要显示失败并允许重试。
