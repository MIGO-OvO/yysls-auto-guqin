# 试听与 MIDI 导出

试听在 Web Audio 的音频线程中合成，无需下载音源。桌面端使用 Windows WebView2 / macOS WKWebView 的 Web Audio 实现，浏览器模式共用同一链路。

## 合成方法

参考 [unsampled-piano 的弦与琴槌建模](https://github.com/mgth/unsampled-piano/blob/b3add8c155f4124a3de959bbf6a5e80d3bc02a06/docs/phase1.md)及[同音弦与衰减](https://github.com/mgth/unsampled-piano/blob/b3add8c155f4124a3de959bbf6a5e80d3bc02a06/docs/phase2.md)中的公开方法，以原生音频节点独立实现简化的模态合成。参考项目采用 GPLv3，本实现继续使用 MIT 协议。

钢琴、古琴与箜篌按弦振动模态叠加：

`f(k) = k × f0 × sqrt((1 + B × k²) / (1 + B))`

基频保持标准十二平均律；刚度系数 B 控制高次泛音偏离整数倍的程度。击弦或拨弦位置决定各模态的激励强弱，高次模态衰减更快。钢琴中高音加入轻微失谐的同音弦，形成拍频和不同衰减速度；古琴偏重较暗的拨弦与木质共鸣，箜篌保留较亮的高次泛音和较长余音。

箫、埙与二胡使用持续泛音激励，分别加入气流或弓弦摩擦噪声。箫与埙的泛音比例、气息、起音和共鸣不同；二胡加入共振峰与渐入揉弦。六种音色分别设置起音、释音、频谱和琴体／管体滤波。噪声由程序生成，没有使用录音采样。

音量变化平滑处理，输出经动态压缩。排程每 50 ms 向音频时钟提交未来 350 ms 的音符，避免为整首长录音一次创建所有节点；最多保留 64 个合成声部，超出时淡出最早的声部。暂停、停止和断开设备会结束声音并清空排程；持续音跟随音符时长和释音段。

MIDI 键盘试听按通道管理按住状态和 CC64 踏板，松键后进入各乐器的释音段。此链路只负责试听。

## MIDI 文件

曲谱导出使用 SMF 0、480 PPQ，按当前 BPM 和网格换算时值。保留编辑音符的重叠关系及完整音长，不套用游戏单声部排程的截断规则。纯按键命令没有可用音高，略过音符而保留空拍。空曲谱和只有纯按键命令的曲谱会提示没有可导出的音符。

MIDI 曲谱和录音会写入当前试听乐器对应的 GM Program Change（下表编号从 1 开始，文件中的值减 1）。标准 GM 中没有古琴、箫、二胡专用编号，因此选择相近乐器：

| 本地音色 | GM 乐器 | 编号 |
| --- | --- | --- |
| 钢琴 | Acoustic Grand Piano | 1 |
| 古琴 | Koto | 108 |
| 箜篌 | Orchestral Harp | 47 |
| 箫 | Shakuhachi | 78 |
| 二胡 | Fiddle | 111 |
| 埙 | Ocarina | 80 |

MIDI 不包含本地合成音频。外部播放器的音源决定听到的声音。录音导出保留原始力度、通道和踏板延长后的音长；曲谱导出固定力度为 100。

## 验证

`npm run check` 检查构建与 MIDI 编解码回归。`npm run test:e2e` 使用真实 Chromium Web Audio 渲染六种音色，检查有限输出、起止静音、泛音差异、弦音衰减、管弦持续发声、力度响应、超过 6 秒的长音，以及 44.1 / 48 kHz 下 88 键两端的输出。浏览器用例还覆盖音色持久化、录制窗口共用设置、MIDI 文件下载、踏板松音和长录音的有界排程。

本实现简化了琴槌、声板及弦间耦合，古琴吟猱、二胡滑音等逐音演奏法尚未实现。与游戏录音、真实乐器的听感对照及 macOS 音频待试听验收。
